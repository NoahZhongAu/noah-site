# ADR 0002: Static Content Security Policy with `'unsafe-inline'`

Date: 2026-09-04
Status: Accepted

## Context

PRD §10 requires security headers and a Content Security Policy. PRD S1 requires `/` to be statically generated so the first paint is prebuilt HTML.

In Next.js 16 the recommended strict CSP uses a per-request nonce generated in `proxy.ts`. The Next.js CSP guide states that a fresh nonce requires dynamic rendering. A dynamically rendered page is generated on every request, which gives up the static HTML that S1 exists for and costs LCP on every visit.

Two things on this page are inline and cannot be given a hash at build time:

- Next.js emits inline scripts for hydration and the React Server Components payload. Their contents change with every build and with the content, so a static hash allowlist would break on every deploy.
- `next/font` and Tailwind v4 emit inline `<style>` elements and style attributes, and Framer Motion writes inline styles during animation.

Third parties that must be allowed: Cloudflare Turnstile (`https://challenges.cloudflare.com`, script and frame) and Vercel Analytics and Speed Insights (`https://va.vercel-scripts.com` for the script, `/_vercel/insights` and `/_vercel/speed-insights` for beacons, same origin).

## Decision

The CSP and the other security headers are static, set through `headers()` in `next.config.ts`, applied to every route. No `proxy.ts`. No nonces.

```
default-src 'self';
script-src 'self' 'unsafe-inline' https://challenges.cloudflare.com https://va.vercel-scripts.com;
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:;
font-src 'self';
media-src 'self';
connect-src 'self' https://challenges.cloudflare.com;
frame-src https://challenges.cloudflare.com;
object-src 'none';
base-uri 'self';
form-action 'self';
frame-ancestors 'none';
upgrade-insecure-requests
```

Alongside it: `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`, `X-Frame-Options: DENY`.

The owner's instruction named `'unsafe-inline'` for styles. It is also required on `script-src`, for the hydration scripts described above; without it the page renders as static HTML and never hydrates. `'unsafe-inline'` on `script-src` is the weaker of the two concessions and is the one this ADR exists to record.

## Why this is acceptable here

- The page has no user-generated content and no third-party HTML. The only untrusted input is the contact form body, which is validated on the server and never rendered back into the page.
- The route handler returns JSON only, so an injected script has nowhere to come from.
- Every other directive is strict: no `eval`, no framing, no foreign objects, no foreign fonts or media, and `base-uri` is locked.
- Lighthouse Best Practices does not deduct for `'unsafe-inline'`; the axe and Lighthouse gates in PRD §10 still hold.

## Consequences

- If a future change renders untrusted HTML or adds a script host, this ADR is revisited before the change ships.
- If Next.js gains a build-time hash mode for its hydration scripts, `'unsafe-inline'` on `script-src` can be dropped without touching the rest of this policy.
- The exact directive list above is the acceptance criterion for Milestone 7 step 2; the E2E test asserts the header is present on `/` and contains `frame-ancestors 'none'`.
